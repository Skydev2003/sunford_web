# ลดเวลาสร้างหน้าระหว่าง production build

เจ้าของอนุมัติการทดลองวันที่ 25 พ.ย. 2026 และอนุมัติให้นำค่าที่ผ่านไปใช้ในโค้ดโปรเจกต์วันที่ 26 พ.ย. 2026 ขอบเขตคือการสร้างหน้าใน build และจำนวนการเชื่อมต่อ Warehouse ของ workers

## หลักฐานและการตัดสินใจ

Next.js trace ในเครื่องรอบแรกใช้เวลารวม 226.6 วินาที โดยใช้ 203.3 วินาทีสร้างหน้าล่วงหน้าและ 7.2 วินาทีคอมไพล์ Turbopack จึงทดลองแบ่งงานสร้างหน้าเป็น 2 workers โดยจำกัดแต่ละ worker ให้เปิด Warehouse ได้พร้อมกัน 1 connection

การทดลองรันในสำเนาซอร์สเดียวกันบน Windows ด้วย Node 24.22.3 และ Next.js 16.4.6 ทุกครั้งใช้ Warehouse แบบอ่านอย่างเดียวและปิดการเขียนทะเบียนใบเสนอราคา

| Cache ของ Next.js | สร้างหน้า 1 worker | สร้างหน้า 2 workers | เวลา build รวม 1 → 2 workers |
| ----------------- | -----------------: | ------------------: | ---------------------------: |
| เย็น              |      244.56 วินาที |       149.76 วินาที |       309.50 → 182.48 วินาที |
| อุ่น              |      317.29 วินาที |       148.28 วินาที |       366.82 → 163.13 วินาที |

ช่วงสร้างหน้าเร็วขึ้น 39–53% ผ่านเกณฑ์ลดอย่างน้อย 25% ไม่มี Warehouse timeout หรือ retry ในทั้ง 4 รอบ รายการ 701 routes ใน prerender manifest ตรงกัน

## ค่าที่ใช้และการตรวจ

- `next.config.ts` กำหนด `experimental.cpus: 2` ส่วน `warehouse-postgres.ts` ตรวจ production build phase ของ Next.js เพื่อกำหนดเพดาน 1 connection ต่อ process ขณะให้บริการเว็บไซต์ใช้เพดาน 3 connections ต่อ process
- Build แยกด้วยไฟล์การตั้งค่าและโค้ด Warehouse ที่แก้แล้วผ่าน 716/716 หน้าใน 227.07 วินาที ขั้นสร้างหน้าใช้ 175.18 วินาที ตรวจพบ 2 workers และการเชื่อมต่อพร้อมกันสูงสุด 2 connections โดยไม่มี timeout หรือ retry
- เปิดผล build บน localhost ยืนยัน pool ตอนให้บริการมีเพดาน 3 connections รายการ 701 routes รวมถึงข้อความที่แสดงและ metadata ของ HTML หน้าสินค้า 405 หน้าตรงกับรอบควบคุม สินค้าที่สุ่มเปิด 3 รุ่นตอบ HTTP 200 และ URL รุ่นที่ไม่มีจริงตอบ HTTP 404
- Catalog 231 เคสและ UAT 33 เคสผ่านบน Node 24 พร้อมการตรวจ lint ของไฟล์ที่แก้และ Prettier ทั้งโปรเจกต์
- ผลวัดเป็นเวลาบนเครื่อง การตรวจเวลารวมบน Vercel ทำได้จาก Build Logs เมื่อมีการปล่อย revision นี้ตาม [คู่มือปล่อยรุ่น](../../vercel.md)

## การย้อนค่า

ถ้า build หรือการอ่าน Warehouse ผิดปกติ ให้คืน `experimental.cpus` เป็น `1` และคืนเพดาน Warehouse pool เป็น `3` ทุก phase แล้วตรวจด้วย build แยกอีกครั้ง ทวนการตรวจ production build phase เมื่ออัปเกรด Next.js
