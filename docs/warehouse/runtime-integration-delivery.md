# ผลการเชื่อมสินค้าจริง Warehouse ทั้งเว็บไซต์

วันที่ตรวจ: 10 พฤศจิกายน 2026

เชื่อม API Warehouse ผ่าน repository กลางแล้ว ใช้ SKU กลุ่ม `G...` ที่จับคู่หมวดและรุ่นได้ชัดเจน รายการที่ไม่ชัดถูกพักตามคำสั่งผู้ใช้ ไม่เลือกสินค้าตัวแรกเมื่อมีหลายรหัสตรงกับรุ่นเดียวกัน

| หมวดเดิม             | SKU ที่เปิดใช้ |
| -------------------- | -------------: |
| เครื่องชั่ง          |             41 |
| อินดิเคเตอร์แท่นชั่ง |              6 |
| โครงสร้างแท่นชั่ง    |             21 |
| ระบบ POS             |              3 |
| อุปกรณ์เสริม         |             18 |
| รวม                  |             89 |

API ต้นทางมี 380 SKU พัก 291 SKU: รหัสนอกกลุ่ม G 147, กลุ่ม G ที่ยังจับคู่หมวด/หมวดย่อยไม่ครบ 113 และกลุ่ม G ที่ยังชนกันของรุ่น/เนื้อหา 31 รายการ ดูทุก SKU พร้อมเส้นทางหรือเหตุผลที่พักใน [runtime-product-status.csv](./runtime-product-status.csv) จำนวนนี้เป็นภาพ ณ เวลาตรวจ ไม่ใช่ข้อกำหนดให้เพิ่มสินค้าหรือราคาเมื่อ API ลบรายการออก

## ขอบเขตที่ใช้งานจริง

- Home รายการสินค้า หมวด/หมวดย่อย จำนวนสินค้า ค้นหาด้วยรุ่นหรือ SKU เปรียบเทียบ รายละเอียด ลิงก์เดิม Carousel จัดสเปค และใบเสนอราคา ใช้ชุดสินค้าจาก repository เดียวกัน
- `/products` ใช้สินค้าจริงใน Carousel และแถวการ์ด 5 หมวดแทนแถว mock เดิม
- ตัวเลือกจัดสเปคแสดงเฉพาะรุ่นที่ผูกกับ SKU จริงได้ คู่ความเข้ากันได้ยังใช้ข้อมูลอ้างอิงเดิม เมื่อเลือกหัวอ่านพร้อมชุดเครื่องที่รวมหัวอ่านนั้นแล้ว ใบเสนอราคาคิดชุดเครื่องครั้งเดียว
- `/warehouse-products-test` แสดงเฉพาะชุดที่เปิดใช้บนเว็บไซต์ เพื่อไม่เผยค่าบริการหรือรายการที่พักจาก API ดิบ

## สัญญาข้อมูลและราคา

Warehouse เป็นแหล่งชื่อ SKU หน่วยและราคาขายก่อน VAT ส่วน mapping ระบุหมวด/หมวดย่อยและรุ่นอย่างชัดเจน Prisma/CMS ยังเก็บเนื้อหา สเปกและรูปเดิมสำหรับสินค้าที่จับคู่ตรงกัน โดยรักษาเงื่อนไขซ่อน/ลบไว้ ไม่มีการนำรายการที่ API ไม่ส่งกลับมาจาก snapshot

ชื่อ ราคาและหน่วยมาจากการอ่าน API ปัจจุบัน ไม่กรองสต็อก ราคาเว็บเป็นราคารวม VAT 7% ที่คำนวณจากราคาต้นทาง เก็บราคาสุทธิเป็นจำนวนเต็มหน่วยสตางค์ ใบเสนอราคาอ่าน API ใหม่ ใช้ราคาก่อน VAT คูณจำนวน รวมยอดสุทธิแล้วปัด VAT ครั้งเดียว ตัวอย่าง 100.00 × 2 = สุทธิ 200.00 + VAT 14.00 = 214.00 บาท

Catalog ใช้เวลา revalidate 60 วินาที; cached result กำหนด stale 30, revalidate 60 และ expire 300 วินาที จึงไม่ใช่การอัปเดตแบบผลักทันที ใบเสนอราคาใช้การอ่าน `no-store` เพื่อให้ราคาที่แสดงในเอกสารตรงการอ่านล่าสุด API ที่ข้อมูลไม่ครบ SKU ซ้ำหรือราคาผิดรูปแบบถูกปฏิเสธ ไม่คืนราคาเก่าเป็น fallback เงียบ ๆ

รูปที่ API ส่งใช้ image proxy เฉพาะ SKU ที่อนุมัติและต้นทาง Warehouse ที่ตั้งไว้ รองรับชื่อ loopback ที่เทียบเท่ากันเฉพาะ protocol/port เดียวกัน จำกัดประเภทและขนาดรูป ไม่เปิด proxy URL ทั่วไป

## ผลตรวจ

- Catalog unit tests ผ่าน 134/134 ครอบคลุม mapping, SKU ชนกัน, API validation, ราคา/หน่วย, VAT, hidden/deleted และชุดเครื่องไม่คิดหัวอ่านซ้ำ
- Production build ด้วย Node 24 / Next.js 16.4.3 ผ่าน 398/398 หน้า พร้อม TypeScript; scoped ESLint ผ่านโดยไม่มี warning
- หลังตั้งค่าหน้าจัดสเปคให้รอข้อมูลได้ build ซ้ำผ่าน 398/398 หน้า, root TypeScript ผ่าน และ browser เฉพาะรายละเอียด/รูป/404 กับจัดสเปค/ใบเสนอราคา/PDF ผ่านอีก 2/2 กรณี
- Browser production ผ่าน 35/35 กรณี ครอบคลุม Home ค้นหา/เปรียบเทียบ หมวดทั้ง 5 รายละเอียด SKU/ราคา รูป Carousel wheel/touch จัดสเปค ส่งต่อใบเสนอราคา และ PDF รวมหลายหน้า
- ตรวจ responsive ที่ 390, 834 และ 1440px และตรวจขอบเขต Carousel ที่ 320px; ภาพมือถือ/เดสก์ท็อปเปิดตรวจแล้ว
- Image proxy ของ `G106292` ตอบ 200 `image/webp`; สินค้าที่พัก `/products/acs30-jc21` ตอบ 404 ใน production
- จำลอง API ไม่พร้อมบนเซิร์ฟเวอร์แยก: `/api/products` ตอบ 503 พร้อมข้อความทั่วไป ใบเสนอราคาแสดงข้อผิดพลาดที่ปลอดภัยและไม่แสดงฟอร์ม/ราคาให้พิมพ์
- โหมดพัฒนาแยกด้วย Node 24 / Webpack: เลือกหัวอ่าน → ชุดเครื่อง → ใบเสนอราคา → PDF ผ่านทั้งรอบแรกและรอบอุ่นเครื่อง รายละเอียด ราคาและรูปผ่าน ส่วน URL ที่พักยังตอบ HTTP 200 แบบ streamed not-found ใน dev จึงใช้ production ยืนยัน HTTP 404

อัปเดตหลังผู้ใช้อนุญาตแก้ HMR และรีสตาร์ทพอร์ต 3000: ตรวจพบว่า Next.js บล็อก origin `127.0.0.1` แต่ `localhost` เชื่อมได้ แก้ allowlist เฉพาะ hostname ที่ขาดและเริ่ม server เดิมใหม่ด้วย Node 24 / Turbopack แล้ว HMR ทั้งสอง host และการแก้ source จริงพร้อมรักษาตัวเลือกจัดสเปคผ่าน ไม่จำเป็นต้องเปลี่ยนเป็น Webpack ดูหลักฐานและผลตรวจล่าสุดใน [localhost-hmr-delivery.md](./localhost-hmr-delivery.md) บันทึกข้อจำกัดก่อนหน้านี้เป็นประวัติก่อนแก้แล้ว

หลักฐาน Browser/PDF อยู่ใน `output/warehouse-runtime-20261110/verified-browser/` ตารางสถานะและเอกสารนี้ไม่มี credentials

เปิดพรีวิว production ในเครื่องไว้ที่ [หน้าสินค้า](http://127.0.0.1:3061/products) และ [จัดสเปค](http://127.0.0.1:3061/guides/indicator-platform-compatibility) พรีวิวนี้ใช้สำเนา source ที่ตรวจแล้วพร้อม API/ฐานเว็บไซต์จริง เซิร์ฟเวอร์ development ที่สร้างเพื่อทดสอบถูกปิดแล้ว ส่วน production preview ยังคงเปิดเพื่อให้ผู้ใช้ตรวจ ไม่ได้เผยแพร่สู่ระบบออนไลน์

## การดูแลและย้อนกลับ

หากเพิ่มหรือเปลี่ยน SKU ใน Warehouse รายการใหม่จะยังไม่เปิดอัตโนมัติจนกว่าจะมี mapping ที่ชัดเจน อัปเดต mapping และตรวจผลกระทบรุ่น/URL/ราคาแล้วทดสอบซ้ำ รายการบริการสอบเทียบไม่ใช่บริการที่เว็บไซต์ SUNFORD จะโฆษณา

ผลกระทบเป็นการเปลี่ยนแหล่งอ่านสินค้าทั้งเว็บ การย้อนกลับต้องคืนเฉพาะ delta ของ repository, adapter, mapping และ consumer ในขอบเขตงานนี้จากสำเนาก่อนแก้ โดยรักษางานเดิมของผู้ใช้ไว้ ไม่มีการเขียน Warehouse, migration, แก้ `.env.local`, commit, push หรือ deploy จากงานนี้
